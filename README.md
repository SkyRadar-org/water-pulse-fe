# SkyRadar · NISAR Water Pulse (frontend)

Interactive web app for NASA Space Apps Hanoi 2026, challenge 5 "Dancing with the SARs".
It tracks **flooded rice fields commune by commune** in the Mekong Delta (Long Xuyên Quadrangle + Plain of Reeds)
across NISAR L-band acquisitions, 17 Jun – 3 Nov 2026. For each commune it answers: since when is it flooded,
when was the peak, and did the water drain before the 1 Nov winter-spring sowing window.

Plain Vite + TypeScript (no UI framework), MapLibre GL, Chart.js. The UI is available in Vietnamese and English; commune and province names keep Vietnamese diacritics.

## Run locally

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # type-check + production build into dist/
npm run mock       # regenerate public/mock (synthetic demo data)
```

Requires Node 20+. On Windows PowerShell with script execution disabled use `npm.cmd` instead of `npm`.


## Connect to the real dataset

Start the sibling backend first:

```bash
cd ../skyradar-nisar/water-pulse-be
/workspace/.venvs/nisar/bin/python -m uvicorn app.main:app --reload --port 8000
```

Then run `npm run dev` from this frontend. Vite forwards `/api` and `/static` to port 8000; the app reads
`/api/frontend/*` and the backend's water PNGs. This serves 33 real acquisitions and 140 communes, without tokens.
For an independent checkout, install the backend requirements as described in its README instead of using the cloud venv.

For a production build deployed separately, set `VITE_API_BASE=https://your-backend-host` and `VITE_DATA_MODE=api`
in the frontend build settings. Configure backend `CORS_ORIGINS` to include the frontend origin. These are build-time
variables; the backend must include the frontend adapter from this change. With no API base, production hosting must
reverse-proxy `/api` and `/static` to the backend (Vite's development proxy is not included in `dist`).
To use the original demo, run `VITE_DATA_MODE=mock npm run dev` or build with that variable.

Commune status follows the data team's latest acquisition covering at least 50% of the commune: below 10% water = ready,
10–30% = draining, at least 30% = still wet. Insufficient coverage remains uncertain. Each commune's summary uses that
single reference track (shown in the commune panel); charts and CSV series preserve all tracks. Half-peak dates are a
separate metric. No tracks are averaged.

The adapter excludes calibration acquisitions from the 25 DSWx-S1 validation comparisons. HLS precision and comparable
DSWx area totals are unavailable in the source dataset and display as missing rather than estimated. Area charts sum
observed commune areas for each acquisition. Whole-season summary controls are hidden because the committed summary
PNGs combine tracks; no per-track summaries or flood-count PNG are currently supplied. Permanent water is excluded
from the real water overlays.

## Data modes

The default is now the real backend API. Set `VITE_DATA_MODE=mock|static|api` before starting Vite or building (see [src/config.ts](src/config.ts)):

| Mode | Source | Use |
| --- | --- | --- |
| `mock` | `public/mock/*` generated by `scripts/make-mock.mjs` | UI work and demos while the backend is not ready. The header shows a **Demo data** badge. |
| `static` | `public/data/*` exported by the data team | Final submission without a live backend. |
| `api` (default) | `VITE_API_BASE` (needs CORS for the frontend domain) | Live backend. |

Every component reads data through [src/data/dataSource.ts](src/data/dataSource.ts); nothing else calls `fetch`.
Types are in [src/data/types.ts](src/data/types.ts). Conventions: dates `YYYY-MM-DD` (UTC acquisition day), percentages 0–100,
areas in km², coordinates EPSG:4326, bounds `[west, south, east, north]`, transparent PNG for the water layer.
Image URLs inside the JSON may be relative to the data base or absolute.

| Function | `mock` / `static` file | `api` endpoint |
| --- | --- | --- |
| `getScenes()` | `scenes.json` | `GET /api/frontend/scenes` |
| `getCommunes()` | `communes.geojson` | `GET /api/frontend/communes` |
| `getCommuneSeries(osmId)` | `series/{osmId}.json` | `GET /api/frontend/communes/{osmId}/series` |
| `getChoropleth(date, track)` | `choropleth/{date}_{track}.json` | `GET /api/frontend/choropleth?date=&track=` |
| `getArea()` | `area.json` | `GET /api/frontend/area` |
| `getSummaryLayers()` | `summary.json` | `GET /api/frontend/summary` |
| `getValidation()` | `validation.json` | `GET /api/frontend/validation` |

Files live under `public/mock/` (mock) or `public/data/` (static).

## Languages

The UI is available in **Vietnamese and English** (VI/EN switch in the header). The first language is taken from `?lang=vi|en`,
then the saved choice, then the browser language. All text lives in [src/locales/en.ts](src/locales/en.ts) and
[src/locales/vi.ts](src/locales/vi.ts) (`vi.ts` is type-checked against `en.ts`, so a missing key fails the build).
Switching language reloads the page and keeps the selected date, commune, layers and tab.

Written for non-technical users: plain-language wording, a 3-step guide (header "Guide" button), a "Find a commune" box,
a one-paragraph plain summary for every commune, status labels with icons, and technical details folded away on the Validation tab.

## Rules the UI follows

- No temporal interpolation: the slider only has real acquisition dates and charts draw straight lines between real points.
- Tracks are never merged: one chart line per track (047D, 083A, 148D).
- Images before 22 Oct 2026 are labelled **Provisional**, later ones **Validated**.
- Area figures carry the note that NISAR water area runs ~1.4–1.5× higher than OPERA DSWx-S1.
- Colour is never the only carrier of meaning (legends and labels everywhere).

```
scripts/make-mock.mjs  demo data generator
```

## Deploy (Cloudflare Pages)

Target: **nisar-flood.skyradar.vn**, using Pages assets plus an advanced-mode Pages Worker on the same origin.
Run `PYTHON=/workspace/.venvs/nisar/bin/python npm run build:cloudflare`, then `npm run test:cloudflare`.
The build includes the real dataset and precomputed `/api/frontend/*` responses; a separate Python server is unnecessary.
See [Cloudflare deployment](docs/CLOUDFLARE.md) for local runtime tests, account setup, production deployment and custom-domain steps.
Ordinary `npm run build` produces only the frontend; use `build:cloudflare` for this deployment.

## Notes

- Basemap: Esri World Light Gray (no key). CARTO's free tiles now answer "API KEY REQUIRED"; swap `BASEMAP` in `src/config.ts` if you get a key.
- Radar preview comes from NASA GIBS (`NISAR_L2_Geocoded_Polarimetric_Covariance`). When GIBS serves no tile for a date the map shows a small "Radar preview may be missing" note.
- maplibre-gl v6 needs its worker URL set explicitly when bundled (done in `src/map/map.ts`) and must not be pre-bundled by Vite (`vite.config.ts`).
